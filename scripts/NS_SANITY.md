# Проверка Newton–Schulz

`check_newton_schulz.py` проверяет матричное преобразование из Muon в выбранном коммите
`d6a58a321d459a9267243aecc3e0615cffc8f2fc` modded-nanogpt. Это самостоятельная
проверка на синтетических матрицах. Она не запускает обучение и не оценивает
преимущество Muon перед AdamW.

## Запуск

Нужны Python и PyTorch в рабочем окружении. Из корня репозитория:

```bash
python scripts/check_newton_schulz.py --output-dir results/ns_sanity_cpu
```

По умолчанию: CPU, seed 42, один поток, матрицы 16×16, 16×32, 32×16 и 64×64,
3, 5 и 7 итераций, вычисления в FP64, FP32 и BF16. Папка результатов должна
быть новой: скрипт откажется перезаписывать существующий каталог.

При наличии CUDA можно проверить те же операции на GPU:

```bash
python scripts/check_newton_schulz.py --device cuda --dtypes fp64 fp32 bf16 fp16 --output-dir results/ns_sanity_cuda
```

Поддержка типов зависит от оборудования и версии PyTorch. Ошибки отдельных
вариантов записываются в `report.json`; если они есть, код завершения равен 1.
На CUDA режим TF32 отключается для сравнения точностей. Время выполнения здесь
не измеряется: этот скрипт не является бенчмарком производительности.

## Какие матрицы проверяем

- Случайные матрицы с нормальным распределением элементов.
- Матрицы с одинаковыми сингулярными значениями.
- Матрицы со спектром от 1 до 10⁻⁸ в логарифмической шкале.
- Матрицы с половиной нулевых сингулярных значений, с учётом округления при генерации.
- Нулевые матрицы.

Структурированные матрицы строятся через ортонормированные множители и заданный
спектр. Для всех точностей используется одна исходная матрица в FP64. В каждом
варианте её сначала приводят к выбранному типу, затем нормализуют и выполняют
итерации. Тем самым сравнение с FP64 включает и ошибку приведения входа.

## Как проверяем реализацию

Сохраняем коэффициенты, порядок операций, нормализацию и транспонирование
из `source_code/train_gpt2.py`. BF16 повторяет исходную функцию без
`torch.compile`. FP32, FP64 и FP16 — диагностические варианты с другой точностью.
Проверяется результат до дополнительного масштабирования обновления в Muon.

Из исходного файла через AST извлекается только функция
`zeropower_via_newtonschulz5`; тренировочный скрипт не импортируется.
BF16-результат сравнивается с этой функцией при нулевом допуске.
Число итераций передаётся явно: в исходном обучении оптимизатор использует 5,
хотя у самой функции аргумент по умолчанию равен 10.

Отдельная проверка FP64 использует SVD и скалярный полином:

```text
s_next = 3.4445*s - 4.7750*s^3 + 2.0315*s^5
```

Из полученных значений и исходных сингулярных векторов восстанавливается матрица.
Её сравнивают с результатом матричных итераций. Проверяем также сохранение формы,
конечность результата и нулевой выход для нулевого входа. Ошибка спектральной
проверки FP64 останавливает запуск, поскольку это ошибка базового расчёта.

## Результаты

- `summary.csv` — строка на сочетание матрицы, точности и числа итераций:
  минимум и максимум сингулярных значений, численный ранг входа в FP64,
  относительное отличие от FP64 и от частичного полярного множителя через SVD.
- `report.json` — полные входные и выходные спектры, параметры запуска,
  версии Python/PyTorch, устройство, контрольные суммы файлов и ошибки.

Частичный полярный множитель вычисляется как `U_r @ Vh_r` по ненулевым
направлениям; численный ранг определяется с порогом
`max(rows, cols) * eps_fp64 * sigma_max`. Для нулевой опорной матрицы вместо
относительной ошибки сохраняется абсолютная норма ошибки.

Разница с полярным множителем — описательная метрика, а не критерий провала.
Полином Muon намеренно не сходится точно к единице. Малые значения могут не
приблизиться к ней за 3–7 итераций, а нулевые в точной арифметике остаются нулевыми.
Порог «все значения должны попасть в [0.7, 1.2]» здесь не применяется.
Низкая точность может внести небольшие ненулевые направления даже во вход,
построенный как матрица неполного ранга. Итерации затем могут усилить их.

## Локальная проверка, 28 октября 2026 года

Скрипт запущен на CPU, Python 3.12.14, PyTorch 2.15.0+cpu, seed 42,
один поток. Проверены все четыре точности: FP64, FP32, BF16 и FP16,
стандартные формы матриц, все пять типов спектра и 3/5/7 итераций.

Результат: 240 успешных сочетаний, ошибок нет; 60 сравнений FP64 со спектральным
расчётом и 60 точных сравнений BF16 с исходной функцией прошли.
Это проверка корректности скрипта и измерения на синтетических данных;
выводов о качестве обучения GPT из неё не делаем.
